# AI-DLC 감사 기록 (audit.md)

이 파일은 **AI-DLC 진행 중 발생한 모든 상호작용의 원문 기록**이다.
방법론을 얼마나 충실히 따랐는지는 이 파일 하나로 판정된다.

## 기록 규칙

1. **모든 상호작용을 기록한다.** 승인뿐 아니라 질문·거절·수정 요청·역질문까지 전부 남긴다.
2. **사용자 입력은 요약·바꿔쓰기 없이 원문 그대로 남긴다.** 오탈자도 고치지 않는다.
3. 각 기록은 아래 **5개 필드를 반드시 포함**한다.
4. **append(추가)만 한다.** 기존 기록을 덮어쓰거나 지우지 않는다.
   파일 전체를 다시 쓰는 방식(overwrite)은 중복·유실을 만들므로 금지한다.
5. 타임스탬프는 ISO 8601(`YYYY-MM-DDTHH:MM:SS+09:00`)로 적는다.
6. **각 phase 완료 시점마다** 누락된 기록이 없는지 스스로 점검하고,
   빠진 것이 있으면 즉시 보완한 뒤 다음 단계로 넘어간다.

## 5개 필드

| 필드 | 내용 | 흔한 실패 |
|---|---|---|
| `[타임스탬프]` | 상호작용 발생 시각 (ISO 8601) | 날짜만 적기 |
| `[사용자 지시 원문]` | 사용자가 입력한 텍스트 **그대로** | 요약해서 적기 |
| `[AI 제안 요약]` | AI가 제시한 선택지·계획·근거 | 결론만 적고 선택지를 빼기 |
| `[사용자 판단·승인 근거]` | **왜** 그렇게 판단했는지 | "승인합니다" 한 줄로 끝내기 |
| `[최종 결정]` | 확정된 결론 + 다음 단계 | 결정과 근거를 뒤섞기 |

> `[사용자 판단·승인 근거]` 가 "승인합니다"만으로 채워진 기록은 **불완전한 기록**으로 본다.
> AI 제안을 맹목적으로 통과시키지 않았다는 증거가 이 필드에 남아야 한다.

## 기록 템플릿

```markdown
## [Stage Name 또는 Interaction Type]

- **[타임스탬프]**: 2026-01-01T09:00:00+09:00
- **[사용자 지시 원문]**:
  > (원문 그대로 인용)
- **[AI 제안 요약]**: (제시한 선택지와 근거)
- **[사용자 판단·승인 근거]**: (왜 그렇게 판단했는가)
- **[최종 결정]**: (확정 결론과 다음 단계)

---
```

# 형식 예시 (참고용 — 실제 진행 기록 아님)

> 아래 두 항목은 **작성 형식을 보여주기 위한 샘플**이다. 실제 프로젝트 기록이 아니며,
> 실제 기록은 이 구분선 아래 `# 실제 기록` 섹션에 append 한다.
> 샘플은 삭제하지 않고 형식 기준으로 남겨 둔다.

## [예시] Requirements Analysis — 요구사항 확인 질문 응답 및 승인

- **[타임스탬프]**: 2026-01-05T14:32:10+09:00
- **[사용자 지시 원문]**:
  > 요구사항 확인 질문 답변할게.
  > Q1은 B. 알림은 앱 푸시만 하고 이메일은 이번 범위에서 빼자.
  > Q2는 C인데 조건이 있어. 동시 편집은 지원하되 충돌나면 나중에 저장한 쪽이 이기는 게 아니라
  > 사용자한테 물어봐야 해. 자동 병합은 하지 마.
  > Q3은 잘 모르겠어. 우리가 지금 결정해야 하는 거야? 나중에 정해도 되면 미루고 싶어.
- **[AI 제안 요약]**:
  요구사항 확인 질문 3건을 다지선다로 제시했다.
  Q1(알림 채널): A) 이메일만 B) 앱 푸시만 C) 둘 다 D) 미정 —
  기간 제약(4주)을 근거로 B를 권장.
  Q2(동시 편집): A) 미지원(잠금) B) 마지막 저장 우선 C) 충돌 감지 후 사용자 선택 D) 자동 병합 —
  데이터 유실 위험을 근거로 C를 권장.
  Q3(데이터 보존 기간): A) 30일 B) 1년 C) 무기한 D) 미정 —
  스토리지 비용과 규정 영향이 있어 Inception에서 결정할 것을 권장.
- **[사용자 판단·승인 근거]**:
  Q1=B: 4주 안에 이메일 발송 인프라(도메인 인증·바운스 처리)까지 만들 여력이 없다.
  알림은 앱 내 사용률이 높은 편이라 푸시만으로 핵심 여정이 성립한다고 판단.
  이메일은 out of scope 로 `00-business-brief.md` 에 명시하기로 함.
  Q2=C + 조건: 자동 병합은 사용자가 결과를 예측할 수 없어 신뢰를 잃는다고 판단.
  "나중에 저장한 쪽이 이긴다"는 조용한 데이터 유실이라 명시적으로 배제.
  충돌 시 사용자 선택 UI가 추가 비용이지만, 데이터 유실보다 저렴하다고 봄.
  Q3: 보존 기간은 법무 확인이 필요해 이 자리에서 결정하지 않기로 함(AI 권장을 그대로 수용하지 않음).
- **[최종 결정]**:
  Q1 → 앱 푸시만 (`FR-012`), 이메일 알림은 out of scope.
  Q2 → 충돌 감지 후 사용자 선택 (`FR-018`). 자동 병합·last-write-wins 는 명시적 금지 조건으로 요구사항에 기재.
  Q3 → **보류**. `aidlc-docs/inception/requirements/requirements.md` 에 `NFR-004 (미정, 법무 확인 대기)` 로 기록하고,
  Requirements Analysis 는 이 항목을 미정 상태로 둔 채 승인. 결정 기한 2026-01-12.
  다음 단계: User Stories 로 진행.

## [예시] Requirements Analysis — 단계 완료 시 audit 누락 점검

- **[타임스탬프]**: 2026-01-05T14:40:02+09:00
- **[사용자 지시 원문]**:
  > (사용자 입력 없음 — phase 완료 시점의 자체 점검)
- **[AI 제안 요약]**:
  Requirements Analysis 완료 전 audit.md 자체 점검을 수행했다.
  이 단계에서 발생한 상호작용 4건(초기 지시 1, 확인 질문 제시 1, 답변 1, 범위 축소 요청 1) 중
  "범위 축소 요청" 1건이 audit.md 에 누락된 것을 발견해 보완 기록을 append 했다.
- **[사용자 판단·승인 근거]**:
  (자체 점검 항목 — 사용자 판단 불필요. 누락분 보완 후 사용자에게 보고함)
- **[최종 결정]**:
  누락 1건 보완 완료. Requirements Analysis 기록 4/4 확보.
  `aidlc-docs/aidlc-state.md` 의 Requirements Analysis 체크박스를 `[x]` 로 갱신하고 다음 단계로 진행.

### 참고: 나쁜 기록 예 (이렇게 쓰면 안 된다)

```markdown
## Requirements Analysis
- **[타임스탬프]**: 2026-01-05
- **[사용자 지시 원문]**: 사용자가 요구사항을 확인해줌
- **[AI 제안 요약]**: 요구사항 정리함
- **[사용자 판단·승인 근거]**: 승인합니다
- **[최종 결정]**: 승인됨
```

무엇이 잘못됐는가:
시각이 아니라 날짜만 있고 · 지시 원문 대신 요약이 들어갔고 · AI가 어떤 선택지를 제시했는지 알 수 없고 ·
판단 근거가 없어 **사람이 검토했다는 증거가 되지 않으며** · 무엇이 결정됐는지 추적할 수 없다.
